# scythe

_headless video factory_

![scythe](assets/scythe.jpg)

> Drop assets + a cutlist into a project, get a broadcast-ready MP4. One ffmpeg pass, zero frame loops.

## Quick Start

```bash
curl -sSL https://raw.githubusercontent.com/sub0xdai/scythe/master/scythe.sh | bash -s my-video
```

Installs host deps, clones the engine if missing, and scaffolds `projects/my-video/`. No assets are installed - this is your video, so provide your own:

```bash
cp ~/clips/*.mp4 projects/my-video/raw_footage/
cp ~/Downloads/soundtrack.mp3 projects/my-video/audio/
cp ~/Downloads/voiceover.wav projects/my-video/audio/   # optional
python3 scripts/generate_cutlist.py projects/my-video   # valid default cutlist from your assets
./render.sh projects/my-video
```

Prefer an LLM cutlist? Feed `prompts/brutalist-video-prompt.md` to any LLM, save the JSON as `projects/my-video/prompts/cutlist.json`, then `./render.sh projects/my-video`.

## What It Does

1. Validates the cutlist against a JSON schema before any render work. Bad input fails fast, naming every violation.
2. Compiles the timeline into one ffmpeg filtergraph: filters, Ken Burns with easing, transitions, LUT grading.
3. Burns captions from a generated .ass file: wrapped, safe-zone positioned, karaoke word-flash, lower-thirds.
4. Masters audio in the same pass: sidechain ducking, loudnorm to -14 LUFS, voice cleanup.
5. Auto-detects GPU encoders (NVENC, VAAPI, QSV, VideoToolbox) with a dry-run check. No GPU means libx264, unchanged.
6. Emits JSON progress events on stdout in machine mode (`--json`).

## Project Structure

```
projects/my-video/
├── config.json       # Style: theme, resolution, audio, transitions
├── audio/            # soundtrack.mp3 + voiceover.wav
├── prompts/          # cutlist.json (generated by LLM)
├── raw_footage/      # Your video clips + images
├── overlays/         # Logos, textures, grids
└── output/           # master.mp4 + web.mp4 (+ subtitles.ass)
```

## config.json

```json
{
  "preset": "widescreen",
  "theme": "clean_editorial",
  "lut": "grade/teal.cube",
  "transition_mode": "cross_dissolve",
  "transition_duration": 0.3,
  "ken_burns_easing": "cubic",
  "lufs_target": -14,
  "duck_threshold": 0.02,
  "duck_ratio": 2,
  "voice_cleanup": true,
  "safe_zone_bottom": 0.25
}
```

Precedence: defaults < theme < config.json < CLI flags.

### Themes

| Theme | Look |
|-------|------|
| `brutalist` | Default: monochrome crush, hard cuts, serif |
| `clean_editorial` | Sans-serif, grayscale default, cross-dissolves, cubic easing |
| `documentary` | Serif, deeper audio headroom (-16 LUFS), slow dissolves |
| `minimalist` | Sans-serif, thin stroke, color crush, hard cuts |

Themes live in `themes/`. `"theme"` accepts a name or a path to a custom JSON file.

### Presets

| Preset | Resolution | Use Case |
|--------|-----------|----------|
| `widescreen` | 1920x1080 | **Default**: YouTube, trailers, desktop |
| `vertical` | 1080x1920 | Shorts, Reels, TikTok (opt-in) |
| `square` | 1080x1080 | Instagram feed |
| `story` | 1080x1920 | Sans-serif, softer branding |
| `cinematic` | 1920x1080 | Large serif, dramatic |

### Outputs

Every render emits one MP4 per entry in `outputs` — by default a desktop-first pair:

```json
"outputs": [
  { "name": "master", "crf": 18 },
  { "name": "web", "max_height": 720, "crf": 23 }
]
```

- `master.mp4` — full project resolution (1920x1080 by default), higher quality
- `web.mp4` — scaled to max 720p height (1280x720), same 16:9 geometry
- Omit an entry's resolution to use the project resolution as-is; `max_height` scales down only (never upscales)
- One ffmpeg pass: decode, filters, and audio mix run once; a `split` node fans the final frames to each output
- Set a single entry to render one file (e.g. just `{"name": "master"}`)

Override the default pair with any list of entries, e.g. a 4K master:

```json
"outputs": [
  { "name": "master_4k", "resolution": [3840, 2160], "crf": 18 },
  { "name": "web", "max_height": 1080, "crf": 23 }
]
```

## CLI

```bash
python main.py --project projects/my-video --json     # machine-readable progress events
python main.py --project projects/my-video --resolution 1920x1080
python main.py --check-gpu                            # encoder capability report
NOX_GPU=off python main.py --project projects/my-video      # force CPU
NOX_ENCODER=h264_nvenc python main.py --project ...         # force an encoder
```

`NOX_JSON=1` is the env equivalent of `--json`. In machine mode, JSON events are the only stdout content.

## Cut-List Format

The render engine reads `prompts/cutlist.json`:

```json
[
  {
    "start": 0.0,
    "end": 1.0,
    "phase": "hook",
    "text": "YOUR HEADLINE",
    "asset": "raw_footage/clip.mp4",
    "filter": "grayscale",
    "effect": "ken_burns_slow"
  },
  {
    "start": 5.0,
    "end": 5.08,
    "phase": "drop_transition",
    "text": null,
    "asset": null,
    "filter": "white_flash",
    "effect": "strobe"
  }
]
```

Generate cut-lists by feeding `prompts/brutalist-video-prompt.md` to Claude, ChatGPT, or any LLM. Invalid cutlists are rejected before rendering, with every violation named.

### Filter Reference

| Filter | Effect |
|--------|--------|
| `grayscale` | Black & white |
| `color_invert` | Negative image |
| `high_contrast_green` | Crush + green accent |
| `high_contrast_red` | Crush + red accent |
| `white_flash` | Pure white frame |
| `chromatic_aberration` | RGB channel split |
| `film_grain` | 4% noise overlay |
| `color_crush` | Destroy midtones |

### Effect Reference

| Effect | Behavior |
|--------|----------|
| `ken_burns_slow` | 8% zoom over clip (eased) |
| `ken_burns_fast` | 15% zoom over clip (eased) |
| `snap_zoom` | Instant 30% zoom at midpoint |
| `strobe` | Flash frame |
| `word_flash` | Karaoke word-by-word reveal |

Segments can also carry `"lower_third": { "title": "...", "subtitle": "..." }` for animated lower-thirds.

## Audio Convention

- Files in `audio/` with `voice` or `vo.` in the name -> voiceover (full volume, noise-cleaned)
- Everything else -> soundtrack (sidechain-ducked under the voiceover)
- Single file -> plays as-is
- The mix is normalized to -14 LUFS (`lufs_target` to change)

## Verification

```bash
tests/verify.sh
```

The gate: fixture asset generation, the full unit suite, a fixture render with contract checks (resolution, fps, codecs, duration), the missing-asset negative test, and a `--check-gpu` smoke.

## GPU Acceleration

Renders auto-detect hardware encoders with a dry-run check (0.2s null encode). No GPU access means libx264 CPU fallback, unchanged behavior.

When no `--gpu` flag is given, `render.sh` auto-detects usable devices on the host and passes them to the container (additively): the NVIDIA CDI device when the NVIDIA container toolkit is present, and `/dev/dri/renderD128` when it exists. No devices found means no passthrough, and the engine falls back to libx264.

```bash
# No flag: auto-detect (NVIDIA CDI + /dev/dri/renderD128)
./render.sh projects/my-video

# NVIDIA (requires nvidia-container-toolkit on the host)
./render.sh projects/my-video --gpu nvidia

# VAAPI or QSV (passes /dev/dri through)
./render.sh projects/my-video --gpu vaapi
./render.sh projects/my-video --gpu qsv
```

- `python main.py --check-gpu` prints the capability report (encoders, decoders, hwaccels, chosen encoder) and exits non-zero when the chosen encoder is not invokable.
- The VAAPI/QSV profiles assume `/dev/dri/renderD128`. Hosts with a different render node must use `NOX_ENCODER` or edit `src/gpu.py`.

- **Container**: Podman or Docker
